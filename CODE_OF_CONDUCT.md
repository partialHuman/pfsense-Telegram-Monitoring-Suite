# Code of Conduct

## Our Pledge

We as maintainers, contributors, and community members pledge to make participation in the **pfSense Telegram Monitoring Suite** a welcoming, respectful, and harassment-free experience for everyone.

We are committed to fostering an open and inclusive community regardless of:
- Age
- Body size
- Disability
- Ethnicity
- Gender identity and expression
- Level of experience
- Nationality
- Personal appearance
- Race
- Religion
- Sexual orientation
- Technical background

Our goal is to create a collaborative environment where everyone can learn, contribute, and grow.

---

# Our Standards

Examples of behavior that contributes to a positive environment include:

- Being respectful and considerate.
- Providing constructive feedback.
- Welcoming new contributors.
- Accepting constructive criticism gracefully.
- Focusing discussions on improving the project.
- Helping others solve technical problems.
- Sharing knowledge openly.
- Following project guidelines and documentation.

---

# Unacceptable Behavior

The following behaviors are unacceptable:

- Harassment or discrimination of any kind.
- Personal attacks or insults.
- Trolling or inflammatory comments.
- Publishing private information without permission.
- Threats or intimidation.
- Spam or repeated off-topic discussions.
- Deliberately disruptive behavior.
- Sharing malicious code.
- Attempting to exploit project infrastructure.

---

# Scope

This Code of Conduct applies to all project spaces, including:

- GitHub Issues
- Pull Requests
- Discussions
- Documentation
- Community forums
- Project-related communication channels

It also applies when representing the project in public spaces.

---

# Reporting Issues

If you experience or witness behavior that violates this Code of Conduct:

1. Report the incident privately.
2. Include relevant details.
3. Provide links or screenshots when possible.
4. Allow maintainers time to investigate.

Reports will be handled confidentially whenever possible.

---

# Enforcement

Project maintainers are responsible for:

- Reviewing reports fairly.
- Investigating reported incidents.
- Taking appropriate action.
- Communicating outcomes where appropriate.

Possible actions include:

- Friendly reminder
- Warning
- Temporary suspension
- Permanent ban from project participation

The severity of the response depends on the nature and frequency of the violation.

---

# Contribution Expectations

Before submitting contributions:

- Read the documentation.
- Follow coding standards.
- Test your changes.
- Update documentation if required.
- Respect reviewer feedback.
- Keep discussions professional.

---

# Communication Guidelines

When communicating:

- Assume good intentions.
- Ask questions respectfully.
- Explain technical decisions clearly.
- Stay on topic.
- Avoid unnecessary arguments.

---

# Conflict Resolution

If disagreements arise:

1. Focus on technical facts.
2. Discuss possible solutions.
3. Seek consensus.
4. Ask a maintainer for guidance if needed.

---
